# Pipeline Assumptions, Data Mappings, and Thresholds

## 1. DataCo Electronics Preprocessing
- **Filtering**: Historical DataCo supply chain records are filtered strictly to rows where `Category Name == "Electronics"`.
- **Date Shifting**: Order and shipping dates are shifted by a fixed offset so that the earliest order aligns with `2025-04-01`.
- **Time Window**: Records are filtered to the active prediction window from `2025-04-01` through `2025-10-31` (Train: April–August, Validation: September, Test: October).
- **Scope & Storage**: Exactly 811 Electronics order rows are retained after filtering; 2,345 rows outside the date range were excluded. Raw CSV data is excluded from Git tracking via `.gitignore`, while preprocessing code (`src/data/prepare_dataco.py`) and processed output parquet schemas are committed.

## 2. Synthetic Network Architecture & Event Generation
- **Network Master Tables**: Master entity files (`suppliers`, `plants`, `warehouses`, `routes`, `products`, `components`, `product_component_map`) are deterministically generated via `src/data/make_master.py`.
- **Geographic Coordinates**: Real latitude/longitude coordinates for cities (e.g., Taipei, Shenzhen, Chennai, San Jose) are used so Open-Meteo weather pulling and spaCy DeBERTa-v3/NER news matching function properly.
- **Causal Disruption Chain**: Daily time-series event logs (`supplier_deliveries`, `production_events`, `daily_inventory`) generated by `src/data/generate_events.py` model a deterministic causal flow:
  $$\text{Severe Weather / Bad News} \longrightarrow \text{Supplier Delay} \longrightarrow \text{Component Shortage} \longrightarrow \text{Production Shortfall} \longrightarrow \text{Stockout}$$
- **Noise & Fallbacks**: Random noise and unexplainable delay events are injected to simulate real-world variance.

## 3. Entity Mapping & External Data Rules
- **Demand Translation**: DataCo order volumes and synthetic regional customer demand are mapped to the nearest regional distribution center (`WH001`–`WH005`).
- **Weather Features**: Open-Meteo daily precipitation ($>50\text{ mm}$) and wind speed ($>60\text{ km/h}$) set `extreme_weather_flag = 1` for suppliers, plants, warehouses, and transport route midpoints.
- **News Entity Linking**: GDELT news headlines are linked to network nodes by matching `country`, `city`, and disruption themes (e.g., semiconductor shortage, labor strikes, port closures).

## 4. Seven-Day-Ahead Risk Label Thresholds
For a feature row on date $t$, targets predict risk events during the lookahead window $(t, t + 7\text{ days}]$ using only past information available on or before $t$:
- **Supplier Failure (`supplier_failure_7d`)**: Set to `1` if supplier delivery delay $\ge 5$ days or a documented facility failure/shutdown occurs within 7 days.
- **Manufacturing Delay (`manufacturing_delay_7d`)**: Set to `1` if actual plant production falls below 85% of planned production within 7 days ($\text{actual} / \text{planned} < 0.85$).
- **Warehouse Stockout (`stockout_7d`)**: Set to `1` if physical inventory drops below the defined safety stock level within 7 days ($\text{inventory} < \text{safety\_stock}$).
- **Transport Delay (`transport_delay_7d`)**: Set to `1` if a scheduled shipment arrives after its expected arrival date ($\text{actual\_arrival} > \text{scheduled\_arrival}$).

## 5. Decision Layer Weighting & Decision Rules
- **Holistic Network Risk Score Formula**:
  $$\text{Network Risk Score} = 0.25 \times \text{Supplier} + 0.25 \times \text{Manufacturing} + 0.20 \times \text{Stockout} + 0.20 \times \text{Transport} + 0.10 \times \text{External}$$
- **Mitigation Decision Logic**:
  - `HIGH` Supplier Risk $\rightarrow$ Trigger switch to pre-approved backup supplier (e.g., reallocate to `SUP004`).
  - `HIGH` Stockout Risk $\rightarrow$ Increase safety stock allocations or execute cross-warehouse stock transfer.
  - `HIGH` Transport Risk $\rightarrow$ Reroute shipments to alternative transit lanes or modes (e.g., switch from ocean to air).
  - `HIGH` Manufacturing Risk $\rightarrow$ De-prioritize low-margin product lines and prioritize high-value customer orders.

## 6. Project Limitations & Exclusions
- **Agmarknet Excluded**: Agmarknet agricultural price data is explicitly dropped because agricultural market prices do not serve as a defensible proxy for electronics/smartphone component pricing.
- **Demonstration Scope**: Results prove that the technical data, NLP, forecasting, graph, and stacking pipeline functions end-to-end; they do not represent real-world predictive accuracy on live commercial infrastructure.
